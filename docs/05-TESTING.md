# 05 — Testing Strategy

Owner: QA lead. Status: Approved.

## 1. Policy

1. **Every phase adds tests; no phase removes or weakens tests.** CI runs the full suite on every pull request. A phase is not done until the whole suite is green (see Definition of Done in `04-ROADMAP.md`).
2. **Tests first for pure modules.** `engine`, `midi`, `mapping`, `kits` are written test-first. UI components get tests once behaviour is stable within the phase.
3. **No test may depend on real hardware, real audio output, or network.** Web MIDI and Web Audio are injected/faked.
4. **Flaky tests are bugs.** A test that fails intermittently is fixed or quarantined with an issue link within the same phase; never retried blindly in CI.
5. **Coverage gate** on `src/engine`, `src/midi`, `src/mapping`, `src/kits`: lines ≥ 90 %, branches ≥ 85 %. Whole project: lines ≥ 80 %.

## 2. Pyramid

| Level | Tool | What | Speed |
|---|---|---|---|
| Unit | Vitest | Pure functions, engine with fake AudioContext, MIDI parsing, resolver, schemas, stores | < 5 s total |
| Component | Vitest + Testing Library + jsdom | Pads, mixer, selectors, editor forms; rendering and interaction, no audio | < 10 s |
| E2E | Playwright, Chromium + Firefox + WebKit | Real browser, real Web Audio (silent/offline), fake Web MIDI; user stories end-to-end | < 3 min |
| Visual | Playwright screenshots (Chromium only) | Pad grid idle/hit/unavailable, status bar states, both breakpoints | part of E2E |
| Performance | Playwright + in-app metrics hook; Lighthouse CI; size-limit | `06-METRICS.md` | < 2 min |

## 3. Fakes and fixtures

### 3.1 Fake AudioContext (`tests/unit/fakes/FakeAudioContext.ts`)
Implements the interface in `src/engine/audioContext.ts`:
- `currentTime` advanced manually via `fake.advance(seconds)`.
- `createBufferSource()` returns a recording node: `start(t)`, `stop(t)`, `connect()`, `buffer`, plus an `events` array.
- `createGain()` records `gain.value`, `setTargetAtTime`, `linearRampToValueAtTime` calls with timestamps.
- `decodeAudioData(bytes)` resolves to a stub `AudioBuffer` with `duration` from a lookup table.
- `state`, `resume()`.

Tests assert on the recorded call lists (e.g. "choke called setTargetAtTime(0, t, 0.012) on the open-hat gain node").

### 3.2 Fake MIDI (`tests/e2e/fixtures/fakeMidi.ts`)
Installed with `page.addInitScript` **before** the app loads. Defines `navigator.requestMIDIAccess` returning an object with `inputs` (Map), `outputs`, `onstatechange`, and a test-only global `window.__fakeMidi` with:
- `addInput({ id, name, manufacturer })` → fires `statechange` with `port.state = 'connected'`.
- `removeInput(id)`.
- `send(id, bytes, timeStamp?)` → calls the input's `onmidimessage` with a `MIDIMessageEvent`-shaped object (`data: Uint8Array`, `timeStamp`).
- Helpers: `noteOn(id, note, vel)`, `noteOff(id, note)`, `cc(id, num, val)`.
- `denyPermission()` makes `requestMIDIAccess` reject with `SecurityError`.
- `unsupported()` deletes `navigator.requestMIDIAccess`.

Also a unit-level `FakeMidiAccess` in `tests/unit/fakes/` implementing the interface used by `MidiManager`.

### 3.3 Test kit (`tests/fixtures/kits/test-kit/`)
Three 50 ms WAV files generated by a script (`scripts/make-test-kit.ts`): sine 100 Hz ("kick"), noise burst ("snare"), sine 8 kHz decaying 400 ms ("hihat.open"), plus `hihat.closed` as a 30 ms burst. Manifest covers: 2 velocity layers, 2 round robins on one articulation, hihat openness `[closed, open]`, choke rules. `index.json` fixture lists it. E2E runs with `VITE_KITS_BASE_URL` pointing to the fixture directory so no real kit is downloaded in CI.

### 3.4 Audio in E2E
Chromium is launched with `--autoplay-policy=no-user-gesture-required --use-fake-device-for-media-stream --disable-features=AudioServiceOutOfProcess` and `--mute-audio`. Assertions about *audio behaviour* in E2E are made through a test hook `window.__drumr.engine.stats()` exposed only when `import.meta.env.MODE === 'test'`: `{ activeVoices, lastTrigger: { articulationId, velocity, atTime }, chokes: number }`.

## 4. Test naming and IDs

File names mirror source: `src/engine/Choke.ts` → `tests/unit/engine/Choke.test.ts`. E2E specs are named by story: `tests/e2e/US-07-hihat-choke.spec.ts`. Each `test()` title starts with the story id it covers, e.g. `"US-07: closed hit chokes ringing open hat within 40 ms"`. The roadmap lists required test titles per phase; CI greps for them (`scripts/check-required-tests.ts`) and fails if one is missing.

## 5. CI pipeline (`.github/workflows/ci.yml`)

```
on: pull_request, push to main
jobs:
  quality:   pnpm lint && pnpm typecheck
  unit:      pnpm test:unit --coverage   → upload coverage; fail under thresholds
  build:     pnpm build && pnpm size-limit → upload dist artifact
  e2e:       needs build; pnpm exec playwright install --with-deps; pnpm test:e2e (3 browsers, retries: 0)
  required:  pnpm check:required-tests (phase manifest in docs/04-ROADMAP.md → tests present)
  deploy:    only on main; needs all above; deploy dist to GitHub Pages
  lighthouse: only on main; needs deploy; lhci autorun against the live URL; fail < thresholds
```

Branch protection on `main`: all jobs required, no force push.

## 6. Manual verification checklist (run by the author before tagging a release)

Automated tests cannot verify real-hardware latency or audio quality. Before each tagged release:
- [ ] Real controller: all 16 pads trigger the expected voices on each bundled kit.
- [ ] Hi-hat strip sweeps through every openness level; closed hit chokes open.
- [ ] Fast 16th-note rolls at 180 BPM on snare: no dropped notes, no clicks.
- [ ] Switch kit mid-play: no glitches.
- [ ] Safari: keyboard/touch mode works, banner correct.
- [ ] Phone: touch pads work, layout correct.
- [ ] Offline reload after first visit works.
Record results in `CHANGELOG.md` under the release.
